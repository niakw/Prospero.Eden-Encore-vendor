# CVE-2026-112366 — Boost 1.90 documentation npm dependency (2026-11-18)

**Status: OPEN, NOT PATCHED.** This is a source-level inventory and containment classification, not a Dependabot dismissal or a PS5-runtime safety certificate.

## Advisory and upstream

- [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf), high severity: ReDoS from single-branch repeated extglobs in npm `picomatch`.
- As of 2026-11-18, the advisory lists **all versions through 4.0.7 as affected and no patched version**, including the 2.3.2 branch. This is **not** the different March 2026 vulnerability [GHSA-c2c7-rcm5-vvqj](https://github.com/advisories/GHSA-c2c7-rcm5-vvqj), which *was* addressed in 2.3.2/4.0.4.
- Upstream proposals (not releases): [micromatch/picomatch #237](https://github.com/micromatch/picomatch/pull/237), [#265](https://github.com/micromatch/picomatch/pull/265), [#267](https://github.com/micromatch/picomatch/pull/267), [#268](https://github.com/micromatch/picomatch/pull/268), [#269](https://github.com/micromatch/picomatch/pull/269). Never import an unmerged candidate into production without review and tests.

## Exposure and boundaries

- These manifests support Boost's optional **Antora documentation generation**, not the compiled PS5 native C++ application. This classification is based on the observed `libs/*/doc` location, their root Antora dependency graph and the absence of `picomatch` in the current Encore engine code search; **it is not proof that every external docs workflow is safe**.
- The imported Boost source tree may contain `build_antora.sh` scripts running `npm ci`. Avoid processing untrusted glob patterns through these vulnerable dependencies. Do not invoke these optional docs generators with untrusted inputs.
- The existing vendor security QA only performs `npm ci --ignore-scripts --dry-run` for two documentation locks, not Antora site generation. This does not demonstrate that the CVE is fixed.
- Do **not** delete or rewrite pinned Boost source snapshots to hide alerts: they carry upstream provenance, hashes, licensing and exact compatibility. A changed documentation lock requires a full authenticated dependency update and verification of the reviewed vendor source-overlay hashes.

## Guardrail and closure criteria

`tests/boost_picomatch_doc_exposure_host.py` checks all six imported lock graphs without executing npm: location, root Antora parent, transitive-only appearance, version, archive source and SHA-512 integrity fields. The vendor security QA executes it on `main`. **Green means the known exposure was inventoried, not patched**; an unrecognized graph or changed version fails until reviewed.

To resolve each alert: wait for a version actually published and identified as fixed by the advisory (including the v2 branch), regenerate the documentation locks with a trusted npm registry, test `npm ci` in an isolated environment plus relevant Antora builds, recompute approved source hashes, qualify both vendor and engine pins, and verify GitHub Dependabot alerts are really resolved. Keep alerts open until those criteria are met.
